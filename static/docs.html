Fast Code Search Documentation

Fast Code Search is a high-performance, in-memory code search service that uses trigram indexing and symbol awareness: results are ranked by definitions, usage and the import graph, and served from memory in milliseconds.

Search Modes

Keyword Search (Default)

Searches for exact text matches across all indexed files. Uses trigram indexing for fast candidate filtering.

  • Case-insensitive matching; the MATCH CASE toggle (or case:yes, case=true) matches case exactly. In the web UI the toggle applies to regex too, and the results header says which applied.
  • Supports glob-based path filtering
  • Can filter to symbol definitions only (plus filename matches)
  • The web UI only submits queries of at least 3 characters (a trigram needs three); the API accepts shorter queries but has to scan candidates without the index

The query is searched for as written, like rg -F: fn main is the phrase fn main, and quotes and a leading - are part of the text ("fn main" finds the words with their quotes, -Wall finds -Wall). Only the operators below are not text.

Command line

The fcs client (built with the server) runs the same searches from a terminal: fcs 'fn main', fcs refs Name, fcs symbols Name, fcs -e 'regex' -g '*.rs'. Output is path:line:col:text when piped and grouped on a terminal; exit codes follow grep (0 matches, 1 none, 2 error). It finds this server through --server, $FCS_SERVER or the configuration, and can search the saved index offline. See docs/CLI.md in the repository.

Regex Search

Enable the Regex toggle to search with regular expression patterns (the syntax of Rust's regex crate). When possible, literals in the regex are used to accelerate the search via trigram filtering. The ? button next to the toggle opens a cheat-sheet with runnable examples.

PatternFinds
fn \w+\(Function definitions (\w+ is one or more word characters)
TODO|FIXMEEither word
(?i)errorerror, Error, ERROR…
\bconfig\bconfig as a whole word, not configure
\{\s*"success":\s*True{ "success": True with any spacing, including none
^import Lines that start with import
\d{3,}Three or more digits in a row
(?s)BEGIN.*?ENDA block from BEGIN to the next END, across lines

Things that catch people out:

  • Case. In the web UI a regex ignores case unless MATCH CASE is on, like plain search. On the API and in fcs -e a regex matches case (as in ripgrep) unless it starts with (?i) or the request says case=false.
  • Some characters are syntax. { } ( ) [ ] . * + ? | ^ $ \ have a meaning; put \ before one to match it literally (\{, \., \(). An unescaped { at the start of a pattern is an error ("repetition operator missing expression"). To search for code exactly as written, turn Regex off instead.
  • Spaces are exact. \{ "a" needs exactly one space after the brace, so it misses {"a". Use \s* for any amount of space (including none) or \s+ for at least one.

When a regex finds nothing, the results area tries a few close variants (flexible spacing, ignoring case, the same text without regex) and offers the ones that find something. When a pattern is invalid, the error points at the problem and offers to search the text literally or with its special characters escaped.

Patterns are matched one line at a time, so \s and . never cross a line break. To match across lines, mention a newline in the pattern (\n, \r, \x0a) or set the s flag, e.g. (?s)begin.*?end or fn \w+\(\)\s*\{\n\s*todo!. Such a pattern is matched against the whole file and each match is reported once, on the line where it starts, with the highlighted range clamped to that line.

Symbols Only

Enable Symbols Only to search only in symbol definitions (functions, classes, methods, types, interfaces, enums, constants, variables, etc.). Filename matches are also included with line_number set to 0. This is much faster when you're looking for definitions rather than all usages.

References

Enable References to list the uses of an identifier: call sites, type mentions and implemented traits, across languages. The name is matched exactly and case-sensitively; file: and lang: still narrow the files.

Dependency Explorer

GRAPH shows the import graph around one file next to its source: what it imports and what imports it, the impact of changing it (with the affected tests), the shortest import chain between two files, and a folder-level module map with import cycles marked. Search results, the deps popover and the file viewer link into it, and Search these files runs a keyword search limited to the files on screen. Imports are resolved for Rust, Python and JavaScript/TypeScript.

Ranking System

For large candidate sets (>5,000 files), the search engine uses a two-phase ranking system to maintain fast response times while preserving result quality.

Mode Icon Description When Used
Auto 🔄 Automatically chooses Fast or Full based on candidate count Default mode
Fast ⚡ Ranks by file metadata, reads the top 2000 files only (fast_rank_files; SEARCH ALL FILES or max_files asks for more) >5,000 candidates (Auto) or explicit
Full 📊 Reads all candidate files for full scoring ≤5,000 candidates (Auto) or explicit

File-Level Scoring Factors

In Fast mode, files are ranked by pre-computed metadata:

  • Symbol density: Files with more symbol definitions rank higher (+4 max)
  • Source location: Files in src/ or lib/ directories get a boost (+2)
  • Import count: Files imported by many others rank higher (+5 max)
  • Test/example penalty: Test and example files are deprioritized (0.7×)

Match-Level Scoring Factors

After reading file content, matches are scored by:

  • Symbol definition: 3× boost for matches in symbol names
  • Exact match: 2× boost when query matches exactly (not a substring)
  • Dependency boost: 1 + 0.5 × log10(dependents) for files imported by other files (1.0 when nothing imports the file)
  • File score: Base file score is carried through

API Reference

Search Endpoint

GET /api/search
Parameter Type Default Description
q string (required) Search query (see Query Syntax; a regex when regex=true)
max integer 50 Maximum results (1-1000)
include string Semicolon-delimited include patterns
exclude string Semicolon-delimited exclude patterns
regex boolean false Treat query as regex pattern. Ignored when symbols is set; combined with references it is a 400.
case boolean Case-sensitive matching; overrides case: in the query. A regex is case-sensitive unless it starts with (?i); case=false adds that flag for you.
max_files integer 2000 Candidate files fast ranking opens (server default fast_rank_files; capped by max_fast_rank_files, reported as max_files_allowed)
word boolean Whole-word matching; overrides word: in the query
references boolean false Return the references (call sites, type mentions, implemented traits) of the identifier in q; results have match_type SYMBOL_REFERENCE. Exact, case-sensitive name; file: / lang: operators still narrow the files. Cannot be combined with regex or symbols (400).
symbols boolean false Search only in symbol definitions and filename matches
rank string auto Ranking mode: auto, fast, or full
context integer 0 Lines of context returned before and after each match (0-10)
offset integer 0 Results to skip before the returned page; ordering is deterministic, so offset=max is page two
timeout_ms integer 0 Stop scanning after this many milliseconds and return the best matches so far (0 = no deadline; capped at 30000)

Note: rank applies to text and regex searches; symbol and reference queries use their own candidate order. Every mode reports rank_mode, total_candidates and candidates_searched in the response.

Example Requests

# Basic search
curl "http://localhost:8080/api/search?q=function"

# Search with path filter
curl "http://localhost:8080/api/search?q=parse&include=src/**/*.rs"

# Force fast ranking
curl "http://localhost:8080/api/search?q=error&rank=fast"

# Regex search for function definitions
curl "http://localhost:8080/api/search?q=fn%20\w%2B®ex=true"

# Page two, and a 2 s deadline
curl "http://localhost:8080/api/search?q=error&max=50&offset=50&timeout_ms=2000"

# Call sites and type mentions of an identifier
curl "http://localhost:8080/api/search?q=SearchEngine&references=true"

Response Format

{
  "results": [
    {
      "file_path": "src/parser.rs",
      "content": "fn parse_token(...)",
      "line_number": 42,
      "match_start": 0,
      "match_end": 5,
      "content_truncated": false,
      "line_match_start": 0,
      "line_match_end": 5,
      "match_column": 0,
      "score": 12.5,
      "match_type": "SYMBOL_DEFINITION",
      "dependency_count": 8
    }
  ],
  "query": "parse",
  "total_results": 1,
  "offset": 0,
  "total_matches": 1,
  "has_more": false,
  "truncated_by_budget": false,
  "elapsed_ms": 23.4,
  "rank_mode": "fast",
  "total_candidates": 15000,
  "candidates_searched": 2000
}

Match positions: match_start/match_end are byte offsets into content, which may be a truncated window of a long line (content_truncated). line_match_start/ line_match_end are byte offsets into the full line, and match_column is the 0-based character column of the match start — use those to place an editor cursor or highlight in the real file. For filename hits (line_number = 0) the offsets refer to the display path.

Paging and totals: results are ordered deterministically (score, then file, then line), so offset pages are stable: ?q=…&max=50&offset=50 is page two. total_results is the length of this page; total_matches is the number of matches across all searched files, when the search ran to completion. Each query has a match budget (and an optional timeout_ms, capped at 30 s); when either stops the scan early, truncated_by_budget is true, total_matches is omitted and has_more is true. Otherwise has_more means offset + total_results < total_matches.

Query Syntax

Plain-text queries (not regex=true) are a literal, like rg -F: several words are one phrase, and quotes and a leading - are part of the text. A few operators, whole words with an argument, narrow the search instead; to search for operator-looking text such as file:x, use a regex.

SyntaxMeaning
file:PATTERN / -file:PATTERN Only / never paths matching PATTERN (a bare word matches anywhere in the path; globs and / are used as written)
lang:rust / -lang:pyOnly / never files of that language (name or extension)
case:yesCase-sensitive matching (also the case=true parameter)
word:yesWhole-word matching (also the word=true parameter)
curl "http://localhost:8080/api/search?q=parse%20lang:rust%20-file:test%20word:yes"

Searching more files: when a query could be in more than 5,000 files, Auto ranking opens the 2,000 most likely (fast_rank_files in the configuration). The response says so (candidates_searched < total_candidates); max_files=N opens more, up to max_fast_rank_files. Paging goes up to offset=100000 (max_page_offset).

Path Filter Patterns

Use glob patterns to filter which files are searched:

Pattern Matches
*.rs All Rust files
src/**/*.py Python files under src/
**/test/** Files in any test/ directory
**/vendor/** Vendor directories (use exclude parameter)

Separate multiple patterns with semicolons: src/**;lib/**

MCP for coding agents

This server speaks the Model Context Protocol at /mcp, so a coding agent can search, read files with line numbers and walk the import graph through it instead of grepping. Add it to Claude Code with claude mcp add --transport http fast_code_search http://127.0.0.1:8080/mcp (use this server's address), or run fcs mcp as a stdio server for clients that only launch commands.

Tool What it does
search_codeSearch with the query syntax; modes text, regex, symbols, references
read_fileNumbered lines of a file, so answers can cite path:line
file_dependenciesWhat a file imports and what imports it, with import lines
change_impactEvery file a change to some files can reach, tests listed separately
import_pathThe shortest chain of imports between two files
dependency_overviewMost connected folders, folder cycles and hub files

All tools are read-only. Requests from a browser page on another origin are refused; like the REST API, there is no authentication, so anyone who can reach this port can read the index.
