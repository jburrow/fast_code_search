Searching

What you type is searched for as written, like rg -F: several words are one phrase, and quotes and a leading - are text. These operators are the only exceptions:

WriteTo get
file:src/Only paths matching it (a word anywhere in the path, or a glob such as file:*.rs)
-file:vendorNever paths matching it
lang:rust, -lang:pyOnly / never files of that language
case:yesMatch case exactly (the default ignores case)
word:yesWhole words only

Combine them: Widget file:src/ -lang:ts case:yes.

ButtonDoes
Match caseMatches upper and lower case exactly, in every mode
RegexThe query is a regular expression (below)
SymbolsOnly the lines that define the name (functions, types, constants…)
ReferencesEvery place the identifier is used, matched exactly
FilterPage size, context lines, and path globs to search only in or skip

Regex

Rust regex syntax, matched one line at a time. The ? next to Regex opens examples you can run.

PatternFinds
fn \w+\(Function definitions
TODO|FIXMEEither word
\bconfig\bconfig as a whole word, not configure
\{\s*"success":\s*True{ "success": True with any spacing
^import Lines that start with import
(?s)BEGIN.*?ENDA block from BEGIN to the next END, across lines
  • { } ( ) [ ] . * + ? | ^ $ \ are syntax: put \ before one to match it, or turn Regex off to search for code exactly as written.
  • Spaces are exact: use \s* for any amount of space, including none.
  • In the web UI a regex ignores case unless Match case is on. On the API and in fcs -e it matches case unless it starts with (?i).

Hover a result's line number to preview the file; click it to open the file there. The strip beside the viewer's scrollbar marks every match in the file.

Command line and coding agents

fcs 'fn main'                 # text search, grep-style output
fcs -e 'TODO|FIXME' -g '*.rs' # regex, only .rs files
fcs symbols Widget            # definitions
fcs refs Widget               # uses
fcs check                     # compare results with ripgrep on your code

This server speaks MCP at /mcp, so a coding agent can search it:

claude mcp add --transport http fast_code_search http://127.0.0.1:8080/mcp

API

The web UI uses the same REST API. The main calls:

CallReturns
GET /api/search?q=mainRanked matches (regex, symbols, references, case, include, exclude, max, offset, context)
GET /api/statsIndex size
GET /api/healthLiveness and the server's version
GET /api/file?file=…A file's contents
GET /api/graph/neighborhood?file=…What a file imports and what imports it

Every endpoint, parameter and response field is in the API reference.
